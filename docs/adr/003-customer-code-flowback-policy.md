# ADR 003: 客户项目代码回流策略

**状态**：accepted
**日期**：2026-04-21
**决策人**：@user

## 背景

公司既做自研产品也接外部客户项目。客户项目代码可能包含可复用的通用组件（驱动、协议栈、算法），但也包含客户 IP、业务逻辑、敏感配置。

问题：**哪些能回流成 wheels、哪些不能？流程是什么？**

## 考虑过的选项

### A. 全部不回流
- 优点：IP 风险零
- 缺点：每次客户项目后"我们又学了什么"归零，违背复利原则

### B. 全部回流
- 优点：积累最快
- 缺点：IP / 合同风险；客户业务细节污染平台

### C. 分类回流（推荐）✓
按分类允许/禁止，流程化剥离

## 决策

**选 C**。分类表：

| 类型 | 能否回流 |
|------|---------|
| 通用协议栈封装（MQTT / BLE service / USB class） | ✅ 可 |
| 驱动（SPI / I2C / 传感器芯片） | ✅ 可 |
| 通用算法（滤波、校验、加密封装） | ✅ 可 |
| 工具函数（ring buffer / log / 数据结构） | ✅ 可 |
| 客户业务逻辑（产品特定行为、工艺流程） | ❌ 不可 |
| 客户 IP（专有协议、VID/PID、密钥、标定数据） | ❌ 不可 |
| 含敏感配置的通用模块 | ⚠️ 剥离后回流 |

**前置条件**：做客户项目前合同要谈通用组件抽取权——"公司在客户项目中开发的通用技术组件（非业务逻辑）可抽取到内部平台，用于后续项目"这类条款。合同没谈的项目，**不**回流（除非客户事后同意）。

**流程**（见 `docs/ai-workflow.md` 任务类型 7）：
1. AI 扫项目找候选
2. 分类过滤
3. 剥离客户特定信息（逐行审查）
4. API 提案 + 人审批
5. 抽到 `wheels/_draft/`
6. 项目内改为引用 wheel

## 后果

### 好
- 每个项目都产生长期资产
- 合同前置保护公司权益
- AI 可自动化大部分抽取工作

### 坏
- 合同谈判多一个条款
- 剥离过程需纪律（AI 可能漏客户信息）
- 客户严格要求代码独占时，整项目无法回流

## 何时应重新评估

- 发生客户 IP 泄漏事件 → 收紧剥离审查
- 回流率 < 10%（客户项目几乎没抽出 wheel）→ 合同或流程问题
- 客户主动要求某 wheel 独家授权 → 特殊处理（分支/定制版）
